# 记忆架构

## 定位

本文档为扩展能力，仅适用于涉及长期运行、复杂上下文追踪或多会话协作的项目。简单项目无需启用。

## 三层记忆模型

### 短期记忆（Working Memory）

- 作用：当前会话的工作缓冲，保持当前任务的即时上下文
- 存储：会话内的对话历史、当前任务状态、临时变量
- 生命周期：单次会话结束即失效
- 使用场景：所有项目的默认行为，无需额外配置

### 情景记忆（Episodic Memory）

- 作用：记录历史交互和工具执行的时序日志
- 存储：按时间线记录关键操作、决策理由、错误和恢复路径
- 生命周期：跨会话持久化，可配置过期策略
- 使用场景：需要回溯决策过程、调试历史行为或支持自纠错的项目

### 长期记忆（Long-term Memory）

- 作用：跨会话的持久化知识库，存储项目事实、决策和领域知识
- 存储：结构化文档（项目文档体系）+ 可选的知识图谱或向量索引
- 生命周期：项目全生命周期，支持语义去重和冲突消解
- 使用场景：长期运行项目、多 Agent 协作项目、需要跨阶段上下文保持的项目

## 记忆读写规则

### 写入

- 阶段交接时，Reporter 角色负责将当前阶段的关键上下文写入情景记忆
- 方案决策时，Explorer 角色负责将已确认事实与推断假设分别标注后写入长期记忆
- 构建完成时，Builder 角色负责将变更摘要写入情景记忆

### 读取

- Agent 启动时，优先从项目文档体系（长期记忆的主要载体）读取
- 遇到模糊点时，可检索情景记忆中的历史决策和错误恢复记录
- 禁止将推断假设当作已确认事实读取

### 过期与冲突消解

- 情景记忆条目可配置 TTL（默认与项目里程碑对齐）
- 长期记忆中的矛盾信息采用双时态标注：事件发生时间 + 系统摄入时间
- 检测到冲突时，优先采用更新时间戳的事实，并在输出中标注冲突

## 与现有文档体系的关系

- 项目文档体系（`docs/` 下的 Markdown 文件）本身就是长期记忆的结构化载体
- 本文档定义的记忆架构不替代文档体系，而是在其基础上补充情景记忆和短期记忆能力
- 文档同步矩阵（`docs/workflow/document-sync-matrix.md`中的规则同时适用于记忆同步）

## 启用条件

当项目满足以下任一条件时，建议启用扩展记忆架构：

- 项目预期运行超过 1 个月
- 多个 Agent 需要跨会话协作
- 需要回溯和审计决策过程
- 任务间存在复杂的上下文依赖
