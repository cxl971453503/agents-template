# 可观测性与追踪

## 定位

本文档为扩展能力，仅适用于需要调试 Agent 行为、审计执行过程或优化执行效率的项目。简单项目无需启用。

## 执行日志规范

### 日志格式

每次 Agent 执行应输出结构化日志，包含以下字段：

```json
{
  "trace_id": "唯一追踪标识",
  "task_id": "当前 Task ID（如有）",
  "agent": "执行角色名称",
  "stage": "当前阶段",
  "step": "步骤描述",
  "input_summary": "输入概要（不超过 200 字）",
  "output_summary": "输出概要（不超过 200 字）",
  "duration_ms": "执行耗时（毫秒）",
  "status": "success | failed | retried | blocked",
  "assumptions": ["本次采用的关键假设"],
  "risks": ["识别到的风险"]
}
```

### 日志存储

- 默认存储位置：`docs/traces/` 目录
- 文件命名：`{trace_id}.json`
- 可通过 `.codex/agents/*.toml` 配置是否启用日志

## 关键决策点快照

### 快照触发条件

在以下节点保存完整状态快照：

- 阶段入口和出口
- 重大方案决策前后
- 首次遇到错误或冲突时
- 任务范围变更时

### 快照内容

```md
1. 快照时间与触发原因
2. 当前阶段和角色
3. 已读取的关键文档及版本
4. 当前采用的关键假设
5. 未解决的冲突或风险
6. 已完成的变更列表
```

### 快照存储

- 存储位置：`docs/traces/snapshots/`
- 文件命名：`{stage}-{timestamp}.md`

## 执行回放

### 回放场景

- 验证 Agent 行为一致性：用相同输入重新执行，对比输出
- 定位问题环节：从快照恢复状态，逐步重放
- 审计决策过程：追溯特定结果的产生路径

### 回放约束

- 回放仅用于调试和审计，不得替代正式阶段流转
- 回放结果不得直接写入项目文档体系
- 回放中发现的修复应走正常阶段流程

## 性能指标

### 采集指标

| 指标           | 说明                        | 采集方式                     |
| -------------- | --------------------------- | ---------------------------- |
| 任务完成率     | 已完成任务 / 总任务数       | 从 `docs/task-board.md` 统计 |
| 阶段平均耗时   | 每个阶段的平均执行时间      | 从执行日志统计               |
| 错误率         | 失败步骤 / 总步骤           | 从执行日志统计               |
| 文档同步率     | 已同步文档变更 / 总文档变更 | 从文档同步检查结果统计       |
| 评审一次通过率 | 一次通过评审的任务比例      | 从 Tester 输出统计           |

### 指标使用

- 指标仅用于项目健康度评估和流程改进
- 不得将指标作为 Agent 执行的硬性门禁
- 建议在阶段 6 交接时附上指标摘要

## 启用条件

当项目满足以下任一条件时，建议启用可观测性：

- 项目预期运行超过 2 周
- 需要审计 Agent 决策过程
- 频繁出现上下文丢失或阶段回退
- 多人协作需要了解 Agent 执行历史
